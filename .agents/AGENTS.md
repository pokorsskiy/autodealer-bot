# Правила работы и разработки для Telegram Ботов

## 1. Режим однократного согласования и автономного выполнения (Workflow)
- **ВАЖНО**: Перед внесением каких-либо изменений в код ИИ **обязан один раз заранее подробно объяснить**, что именно он хочет изменить, в каких файлах и почему.
- После того как пользователь дал явное согласие (написал «да», «согласен», «делай»), ИИ **полностью самостоятельно вносит все изменения**, создаёт и обновляет файлы, коммитит и тестирует результат **за один заход без повторных промежуточных вопросов и остановок**.

## 2. Стандарты разработки Telegram-ботов (pyTelegramBotAPI / aiogram)
- **Безопасность конфигурации**: Все секреты (`BOT_TOKEN`, `ADMIN_ID`, пути к БД) считываются из переменных окружения (`os.getenv`) с резервными значениями (fallback).
- **Безопасное форматирование текста**: Использовать `parse_mode='HTML'` с обязательным экранированием пользовательского ввода через `html.escape()`. Не использовать `Markdown` v1 без необходимости из-за падений на спецсимволах.
- **Работа с Базой Данных (SQLite)**:
  - Обязательно использовать контекстные менеджеры `with sqlite3.connect(...) as conn:` для автоматического закрытия соединений и фиксации транзакций.
  - Автоматически обрабатывать права доступа и путь к файлу БД.
- **Принцип DRY (Не дублировать код)**:
  - Выносить создание инлайн и реплай клавиатур в отдельные функции-фабрики (в модуль `keyboards.py`).
  - Разделять логику работы с БД, логику бота и настройки по отдельным модулям.
- **Отказоустойчивость**:
  - Использовать `bot.infinity_polling(skip_pending=True)`.
  - Не использовать пустые блоки `except:`, перехватывать конкретные исключения или `Exception` с логированием.

## 3. Стиль и вайбкодинг
- Писать чистый, документированный код на Python 3.10+.
- Оставлять наглядные комментарии и эмодзи в логах для быстрого отслеживания работы бота.
