# Правила работы и разработки для Telegram Ботов (Antigravity)

Этот файл определяет правила работы ИИ-ассистента в данном репозитории. Эти правила имеют наивысший приоритет и дополняют стандартные инструкции.

## 1. Рабочий регламент (Workflow)

Регламент определяет, КАК ведётся работа в этом репозитории. Общение с пользователем ведётся на русском языке.

### Жёсткие правила (всегда)
- **НЕ делать git commit / git push / PR без явного разрешения пользователя**, данного непосредственно перед действием. Запрос "Сделай коммит" в рамках большой задачи НЕ является автоматической авторизацией. Всегда показывайте финальный `git diff` / статус и запрашивайте подтверждение.
- **Сначала согласуйте план** нетривиальной задачи (см. Этап 1) и приступайте к реализации только после явного согласия пользователя.
- **Делайте минимальные изменения** — не рефакторите код в несвязанных файлах.
- **Один логический коммит = одно изменение**. Не собирайте всё в один гигантский коммит.
- Если есть два технических решения — опишите оба и предоставьте выбор пользователю.
- **НИКОГДА не коммитьте секреты**, токены, `.env` файлы, базы данных (`*.db`), ключи и прочие чувствительные данные.

### Стоп-фразы для ИИ (остановить выполнение и ждать пользователя)
- ⏸️ **Требую согласования** — план/решение требует утверждения пользователя перед началом работы.
- ⏸️ **Жду утверждения** — работа приостановлена до ответа пользователя.
- ⏸️ **Запрашиваю разрешение на коммит** — всё готово к сохранению изменений, требуется явный "да" на коммит.
- ⏸️ **Ожидаю утверждение коммита** — синоним финального стопа перед коммитом.
*После отправки любой из этих фраз остановите выполнение и не делайте изменений до ответа.*

### Этап 1: Составление плана (до начала работы)
Перед любой нетривиальной задачей изучите контекст, выпишите план и остановитесь на фразе ⏸️ **Требую согласования**.
Формат плана:
```markdown
## План: <название задачи>

### Цель
- Что нужно сделать и какой результат получить

### Шаги
1. ...

### Затрагиваемые файлы
- `path/to/file` — описание изменений

### Краевые случаи / риски
- Описание возможных проблем и путей их решения

### Открытые вопросы
- Вопросы к пользователю (или "нет")

⏸️ Требую согласования
```

---

### Этап 2: Подготовка к коммиту (команда /закрепить)
Когда пользователь пишет "закрепить" (или `/закрепить`), выполните строго по порядку и остановитесь перед коммитом:
1. **Перепроверка кода**: перечитайте `git diff`, убедитесь в отсутствии отладочных принтов, закомментированного мусора, секретов. Изменения должны соответствовать плану.
2. **Обновление памяти**: запишите важные детали в `MEMORY.md` при его наличии.
3. **Обновление документации**: обновите README.md, если добавились фичи, конфиги или зависимости.
4. **Обновление TODO**: сверьтесь со списком задач проекта, перенесите выполненное.
5. **Отчёт и запрос**: сформируйте отчёт по формату ниже и завершите фразой ⏸️ **Запрашиваю разрешение на коммит**.

Формат отчёта:
```markdown
## Отчёт: <название задачи>

### Что сделано
- ...

### Изменённые файлы
- `path/to/file` — описание изменений

### Проверки
- [x] Отладочный код убран
- [x] Секреты отсутствуют
- [x] Соответствует согласованному плану

### Обновлено
- README.md: <что или "без изменений">
- MEMORY.md / AGENTS.md: <что или "без изменений">

### Предлагаемый коммит
`тип: краткое описание` (в формате Conventional Commits, например: `feat: add database backup`)

⏸️ Запрашиваю разрешение на коммит
```

### Команда /автономно — АВТОНОМНЫЙ режим
Когда пользователь просит "работай автономно" или пишет `/автономно`, перейдите в автономный режим для крупных задач (полный рефакторинг, ревью, обновление API).

**Разрешено без переспроса:**
- Принимать технические решения (структура модулей, рефакторинг, удаление мёртвого кода).
- Делать коммиты по ходу работы (один коммит = одно изменение). Правило про отсутствие секретов в коммитах остаётся жёстким.

**ЗАПРЕЩЕНО даже автономно (остановиться и записать вопрос):**
- Необратимые операции (git push, удаление важных данных вне git, изменение критических зависимостей).
- Неоднозначность бизнес-логики (как фича должна работать для конечного пользователя). Примите временный разумный дефолт, пометьте его и идите дальше.

**Как вести вопросы и проблемы:**
В процессе автономной работы все сложные вопросы фиксируйте в два места:
1. В чат в конце ответа: краткий нумерованный список.
2. В корень проекта в файл `отчёт-N.md` (где N — следующий свободный номер от 1. Добавить `отчёт-*.md` в `.gitignore` при необходимости).
Формат каждого пункта в `отчёт-N.md`:
```markdown
## [N.M] <Заголовок проблемы/вопроса>
- **Тип:** вопрос к оператору / проблема / принятое решение
- **Где:** `path/to/file:line`
- **Суть:** описание проблемы или неясности
- **Варианты:** Вариант А (плюсы/минусы), Вариант Б
- **Мой дефолт:** принятое временное решение
- **Статус:** открыт / решён
```

---

### Команда /отчёт о проблеме (генерация отчёта в tmp/)
При запросе зафиксировать баг или проблему, создайте файл `tmp/отчёт-<описание>-<YYYY-MM-DD>.md` (kebab-case) со структурой:
- **Суть проблемы**
- **Где проявляется** (файл, строка)
- **Как воспроизвести**
- **Ожидаемое vs Фактическое поведение**
- **Предлагаемые варианты решения**

Всегда ждите ручного подтверждения перед:
- Любым `git push` или созданием Pull Request.
- Удалением файлов, не находящихся под версионным контролем.

## 2. Стандарты разработки Telegram-ботов (pyTelegramBotAPI)

- **Безопасность конфигурации**: Все секреты (`BOT_TOKEN`, `YOUR_CHAT_ID`, `DB_NAME`) должны считываться из переменных окружения (`os.getenv`) с резервными значениями (fallback) для обеспечения работы на хостингах типа Railway.
- **Безопасное форматирование текста**: Использовать `parse_mode='HTML'` с обязательным экранированием пользовательского ввода через `html.escape()`. Не использовать `Markdown` v1 без крайней необходимости во избежание падений бота на спецсимволах.
- **Работа с Базой Данных (SQLite)**:
  - Обязательно использовать контекстные менеджеры `with sqlite3.connect(...) as conn:` для автоматического закрытия соединений и фиксации транзакций.
  - Предусматривать автоматическую обработку `PermissionError` или `OperationalError` при отсутствии прав записи по указанному пути БД (использовать фолбэк на локальный файл в директории проекта).
- **Принцип DRY (Не дублировать код)**:
  - Выносить создание инлайн и реплай клавиатур в отдельные функции-фабрики (в модуль `keyboards.py`).
  - Чётко разделять логику работы с БД, логику бота и настройки по отдельным модулям.
- **Отказоустойчивость**:
  - Использовать `bot.infinity_polling(skip_pending=True)`.
  - Не использовать пустые блоки `except:`, перехватывать конкретные исключения или `Exception` с логированием через кастомный логгер.

## 4. Описание проекта (Project Overview)

Проект **autodealer-bot** — это мультимодульный репозиторий, содержащий двух независимых Telegram-ботов для автоматизации работы автодилеров и автоподборщиков. Оба бота написаны на Python с использованием библиотеки `pyTelegramBotAPI` и СУБД `SQLite`.

### 1. Основной бот: Dealer Auto Bot (Корневой каталог)
Бот предназначен для привлечения и сбора клиентов автодилера, приходящих из социальной сети Instagram.

*   **Главный файл:** [autodealer.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/autodealer.py) — инициализирует бота, обрабатывает входящие команды, перенаправляет трафик по реферальным ссылкам.
*   **Логика deep-linking:** Бот отслеживает реферальный параметр `?start=INSTA`. При первом переходе пользователя с этим параметром:
    1. Проверяет уникальность пользователя.
    2. Сохраняет его данные в БД.
    3. Отправляет мгновенное HTML-уведомление администратору о новом клиенте.
*   **Архитектурные модули:**
    *   [config.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/config.py) — парсит `.env` и задаёт дефолтные токены и `chat_id` для стабильного запуска на Railway.
    *   [database.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/database.py) — отвечает за инициализацию SQLite-базы `instagram_users.db` и сохранение клиентов. Содержит защитный фолбэк: если запись в директорию БД запрещена, база автоматически создаётся локально в корне.
    *   [keyboards.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/keyboards.py) — генерирует Inline-клавиатуру со ссылками на ресурсы дилера (канал, Instagram, форма заказа).
    *   [logger.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/logger.py) — красивое форматированное логирование событий (MSG, DB, ADMIN, SYSTEM, ERROR) с эмодзи.
    *   [check_project.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/check_project.py) — скрипт самодиагностики. Проверяет синтаксис Python-файлов, наличие переменных окружения, доступность Telegram API и работоспособность SQLite.
*   **База данных:** `instagram_users.db`
    *   Таблица `instagram_users`: `user_id` (PK), `username`, `first_name`, `added_at`.
*   **Админ-команда:** `/db` отправляет актуальный файл базы данных администратору бота (доступ ограничен по `YOUR_CHAT_ID`).

### 2. Бот-презентация: Showcase Bot (Каталог `showcase_bot/`)
Демонстрационный бот (витрина), показывающий потенциальным покупателям (автодилерам) возможности системы автопродаж и собирающий лиды.

*   **Главный файл:** [showcase_bot/bot.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/showcase_bot/bot.py) — реализует интерактивное меню, симуляцию каталога и калькулятора, а также сценарий сбора контактов.
*   **Интерактивные разделы:**
    *   *Тест-драйв:* показ демо-карточки авто (например, BMW X5) и демо-калькулятора расчёта стоимости привоза авто из Кореи/Китая.
    *   *Тарифы и стоимость:* просмотр тарифов («Старт», «Профи», «VIP») с возможностью выбора интересующего варианта.
    *   *Заявка на бота:* сбор телефонного номера пользователя через `ReplyKeyboardMarkup` (запрос контакта) и мгновенное уведомление администратора о новом лиде.
*   **Архитектурные модули:**
    *   [showcase_bot/config.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/showcase_bot/config.py) — конфигурация токенов и пути к БД `showcase_leads.db`.
    *   [showcase_bot/database.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/showcase_bot/database.py) — сохранение лидов при запуске бота и обновление их контактов/интересов при отправке телефона.
    *   [showcase_bot/keyboards.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/showcase_bot/keyboards.py) — клавиатуры главного меню, тарифов, интерактивного демо и реплай-кнопки запроса контакта.
    *   [showcase_bot/check_project.py](file:///c:/Users/proma/PycharmProjects/autodealer-bot/showcase_bot/check_project.py) — скрипт самодиагностики для Showcase Bot.
*   **База данных:** `showcase_leads.db`
    *   Таблица `leads`: `id` (AI), `user_id` (Unique), `username`, `full_name`, `phone`, `interest`, `source`, `created_at`.
*   **Админ-команда:** `/db` отправляет актуальный файл базы данных лидов администратору.
