# Правила работы и разработки для Telegram Ботов

## 1. Режим обязательного согласования изменений (Approval Workflow)
- **ВАЖНО**: Перед внесением каких-либо изменений в существующий код ИИ **обязан заранее подробно объяснить**, что именно он хочет изменить, в каких файлах и почему.
- ИИ должен дождаться **явного подтверждения/согласия пользователя** перед тем, как применять правки в файлах проекта.

## 2. Стандарты разработки Telegram-ботов (pyTelegramBotAPI / aiogram)
- **Безопасность конфигурации**: Все секреты (`BOT_TOKEN`, `ADMIN_ID`, пути к БД) считываются из переменных окружения (`os.getenv`). Должна быть проверка наличия обязательных переменных при запуске.
- **Безопасное форматирование текста**: Использовать `parse_mode='HTML'` с обязательным экранированием пользовательского ввода через `html.escape()`. Не использовать `Markdown` v1 без необходимости из-за падений на спецсимволах.
- **Работа с Базой Данных (SQLite)**:
  - Обязательно использовать контекстные менеджеры `with sqlite3.connect(...) as conn:` для автоматического закрытия соединений и фиксации транзакций.
  - Автоматически создавать директории под БД (`os.makedirs(..., exist_ok=True)`), особенно при работе со сторонними Volume-путями (например, `/data/...`).
- **Принцип DRY (Не дублировать код)**:
  - Выносить создание инлайн и реплай клавиатур в отдельные функции-фабрики (например, в модуль `keyboards.py`).
  - Разделять логику работы с БД, логику бота и настройки по отдельным модулям.
- **Отказоустойчивость**:
  - Использовать `bot.infinity_polling(skip_pending=True)`.
  - Не использовать пустые блоки `except:`, перехватывать только конкретные исключения или `Exception` с логированием.

## 3. Стиль и вайбкодинг
- Писать чистый, документированный код на Python 3.10+.
- Оставлять наглядные комментарии и эмодзи в логах для быстрого отслеживания работы бота.
