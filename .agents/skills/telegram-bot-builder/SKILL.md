# Навык создания и улучшения Telegram-ботов

Этот навык используется при проектировании, создании и модификации Telegram-ботов для расширения функционала и поддержания чистой архитектуры.

## 1. Область применения

Использовать этот навык при создании или изменении Telegram-ботов проекта: основного `autodealer_bot`, `showcase_telegram_bot`, `showcase_webapp_bot` и `showcase_hybrid_bot`.

Не смешивать модули разных ботов. Перед изменением нетривиальной логики сначала согласовать план с пользователем.

## 2. Архитектура проекта бота
При создании или рефакторинге Telegram-бота рекомендуется следующая структурированная схема:
```
autodealer-bot/
├── .agents/
│   ├── AGENTS.md                  # Правила агента и порядок согласования
│   └── skills/
│       └── skills/                # Локальные навыки проекта
├── config.py                      # Конфигурация и переменные окружения
├── database.py                    # Логика и запросы SQLite
├── keyboards.py                   # Фабрика клавиатур
├── helpers.py                     # Утилиты (HTML-экранирование, уведомления)
├── bot.py                         # Главный файл бота (хэндлеры)
├── .env.example                   # Шаблон конфигурации
└── requirements.txt               # Зависимости Python
```

## 3. Типовые модули и фичи

### А. Реферальная система и deep-linking
- Анализ `message.text.split()[1]` в команде `/start`.
- Сохранение UTM-меток / источников переходов (`INSTA`, `VK`, `TG_ADS`).
- Проверка уникальности пользователя перед записью в БД.

### Б. Модуль Уведомлений Администратора
- Формирование красивых HTML-сообщений.
- Отправка алертов о новых пользователях с их ID, имени и юзернейме.
- Выгрузка файла БД по запросу админа `/db`.

### В. Безопасная работа с SQLite
- Регулярный вызов `conn.commit()`.
- Использование `INSERT OR REPLACE` или `INSERT OR IGNORE` для предотвращения дубликатов `user_id`.
- Экспорт БД прямо в чат Telegram для бэкапа.

## 4. Чек-лист перед каждым предложением изменений
1. Проверить, что настройки и секреты берутся из окружения или локального `.env`, а не зашиты в код.
2. Проверить экранирование пользовательского ввода через `html.escape` перед `parse_mode='HTML'`.
3. Для callback-кнопок вызывать `answer_callback_query`.
4. Проверить обработку сетевых ошибок Telegram через `error-handler`.
5. Подготовить краткое описание планируемых изменений.
6. Дождаться подтверждения пользователя перед изменением кода.

## 5. Локальный запуск

- Основной бот: `python -m autodealer_bot.autodealer`.
- Telegram showcase: `python showcase_telegram_bot/bot.py`.
- Web App showcase: `python showcase_webapp_bot/bot.py`.
- Hybrid showcase: `python showcase_hybrid_bot/bot.py`.

Для Web App отдельно публиковать `showcase_webapp_bot/web/` по HTTPS; Python-бот должен работать постоянно.
