# Разработка Telegram-бота

Соблюдать корневой `AGENTS.md`. Считать `showcase_bot/` главным ботом; дополнительные showcase-модули изменять только по прямому запросу.

## Рабочий процесс

1. Изучить связанные обработчики, клавиатуры, конфигурацию и слой данных.
2. Для нетривиальной правки показать краткий план и дождаться подтверждения.
3. Внести минимальное изменение без переноса кода между ботами.
4. Проверить синтаксис командой `python -m compileall showcase_bot`.
5. Запустить `python showcase_bot/check_project.py`, если проверке не мешают отсутствующие секреты или внешние сервисы.
6. Не запускать polling без прямой просьбы пользователя.

## Границы модулей

- Хранить обработчики и запуск в `showcase_bot/bot.py`.
- Загружать настройки окружения в `showcase_bot/config.py`.
- Хранить SQL и миграции в `showcase_bot/database.py`.
- Создавать клавиатуры в `showcase_bot/keyboards.py`.
- Настраивать логирование в `showcase_bot/logger.py`.
- Добавлять вспомогательный модуль только при повторном использовании логики.

## Безопасность

- Получать токены, идентификаторы администраторов и другие секреты только из окружения или локального `.env`.
- Экранировать пользовательские значения через `html.escape` перед включением в HTML-сообщение.
- Валидировать команды, callback-данные, контакты и данные Web App до записи или отправки.
- Применять `db-migrator` при изменении схемы или существующих данных SQLite.
- Применять `error-handler` при добавлении обработчиков, callback-сценариев, сетевых вызовов и polling.
- Применять `ui-designer` при изменении сообщений, меню, кнопок, карточек и Web App.

## Telegram-сценарии

- Разбирать аргумент `/start` безопасно: проверять его наличие, допустимый формат и длину.
- Хранить в callback-данных короткий стабильный идентификатор, а состояние сценария — на сервере.
- Отвечать на каждый callback через `answer_callback_query`.
- Не редактировать сообщения с reply-клавиатурой; для смены интерфейса отправлять новое сообщение и при необходимости использовать `ReplyKeyboardRemove`.
- Не отправлять пользователю traceback, внутренние пути, SQL, токены и текст внутренних исключений.
