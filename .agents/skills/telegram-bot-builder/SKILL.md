# Навык создания и улучшения Telegram Ботов

Этот навык используется при проектировании, создании и модификации Telegram-ботов для расширения функционала и поддержания чистой архитектуры.

## 1. Архитектура проекта бота
При создании или рефакторинге Telegram-бота рекомендуется следующая структурированная схема:
```
autodealer-bot/
├── .agents/
│   ├── AGENTS.md                  # Правила агента и порядок согласования
│   └── skills/
│       └── telegram-bot-builder/  # Данный навык
│           └── SKILL.md
├── config.py                      # Конфигурация и переменные окружения
├── database.py                    # Логика и запросы SQLite
├── keyboards.py                   # Фабрика клавиатур
├── helpers.py                     # Утилиты (HTML-экранирование, уведомления)
├── bot.py                         # Главный файл бота (хэндлеры)
├── .env.example                   # Шаблон конфигурации
└── Procfile                       # Конфиг деплоя (worker: python bot.py)
```

## 2. Типовые модули и фичи

### А. Реферальная система & Deep-linking
- Анализ `message.text.split()[1]` в команде `/start`.
- Сохранение UTM-меток / источников переходов (`INSTA`, `VK`, `TG_ADS`).
- Проверка уникальности пользователя перед записью в БД.

### Б. Модуль Уведомлений Администратора
- Формирование красивых HTML-сообщений.
- Отправка алертов о новых пользователях с их ID, имени и юзернейме.
- Выгрузка файла БД по запросу админа `/db`.

### В. Безопасная работа с SQLite
- Регулярный вызов `conn.commit()`.
- Использование `INSERT OR REPLACE` или `INSERT OR IGNORE` для предотвращения дубликатов `user_id`.
- Экспорт БД прямо в чат Telegram для бэкапа.

## 3. Чек-лист перед каждым предложением изменений
1. Проверить, все ли переменные берутся из `os.getenv`.
2. Проверить экранирование символов в именах пользователей (`html.escape`).
3. Подготовить краткое и понятное описание планируемых изменений для пользователя.
4. Дождаться подтверждения пользователя перед изменением файлов кода!
