# Безопасные миграции SQLite

Сохранять существующие данные и делать миграции повторяемыми. Не удалять, не очищать и не пересоздавать рабочую БД без отдельного разрешения пользователя.

## Перед изменением

1. Найти фактический путь к БД и код инициализации схемы.
2. Изучить таблицы, колонки, индексы и внешние ключи через `sqlite_master` и соответствующие `PRAGMA`.
3. Определить текущую версию через `PRAGMA user_version`.
4. Не открывать и не изменять рабочую БД в автоматических тестах.

## Резервная копия

- Создавать резервную копию перед рискованной миграцией через `sqlite3.Connection.backup`, пока исходное соединение открыто.
- Добавлять к имени копии дату и время, не перезаписывать предыдущую копию.
- Хранить резервные копии локально и не добавлять `*.db`, `*.db-wal`, `*.db-shm` и копии БД в Git.
- Проверять, что копия открывается, до изменения схемы.

## Миграция

- Выполнять каждый шаг только для ожидаемой предыдущей версии схемы.
- Проверять наличие таблицы, колонки или индекса до `CREATE` либо `ALTER TABLE`.
- Выполнять связанные изменения в одной транзакции; при ошибке делать rollback и логировать исключение.
- Обновлять `PRAGMA user_version` только после успешного завершения всех шагов.
- Для сложного изменения таблицы создавать новую таблицу, переносить проверенные данные, сверять количество строк и только затем заменять старую.
- Использовать параметры `?` для значений. Имена таблиц и колонок брать только из фиксированного набора, не из пользовательского ввода.

## Запись данных

- Использовать обычный `INSERT`, если дубликат означает ошибку.
- Использовать `INSERT ... ON CONFLICT DO UPDATE` для осознанного обновления существующей записи.
- Не применять `INSERT OR REPLACE` по умолчанию: операция может удалить старую строку и создать новую.
- Не применять `INSERT OR IGNORE`, если важно заметить потерю или отклонение данных.

## Проверка

1. Сначала выполнить миграцию на временной копии БД.
2. Повторно выполнить миграцию и убедиться в её идемпотентности.
3. Проверить ожидаемые колонки, индексы, количество строк и ключевые значения.
4. Выполнить `PRAGMA integrity_check` и при внешних ключах `PRAGMA foreign_key_check`.
5. Сообщить пользователю путь резервной копии и результат проверки.
