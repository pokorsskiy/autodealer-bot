# Обработка ошибок Telegram-бота

## Классификация

- Обрабатывать ошибки пользовательского ввода без traceback и показывать понятную подсказку.
- Обрабатывать `ApiTelegramException` отдельно от ошибок HTTP, SQLite и конфигурации.
- Считать отсутствие обязательной конфигурации ошибкой запуска, а не скрывать её внутри обработчика.
- Не использовать пустой `except:` и не продолжать работу после повреждения состояния.

## Хэндлеры

- Логировать неожиданное исключение через `logger.exception` с названием обработчика и безопасными идентификаторами.
- Получать чат защитно: у callback может быть `message`, `inline_message_id` либо отсутствовать доступный чат.
- Отвечать на callback через `answer_callback_query` как можно раньше; при ошибке основного сценария пытаться завершить индикатор загрузки безопасным сообщением.
- Показывать пользователю короткую нейтральную ошибку только при наличии доступного чата.
- Не дублировать уведомление, если пользователь и администратор имеют один chat ID.
- Не превращать общий декоратор в механизм, который молча скрывает критические ошибки запуска, миграции или конфигурации.

## Telegram API и сеть

- Повторять только временные и идемпотентные операции.
- Ограничивать число попыток, применять увеличивающуюся задержку с небольшим случайным разбросом.
- Не повторять без изменения запроса ошибки валидации, запрета доступа и блокировки бота пользователем.
- Учитывать серверную рекомендацию задержки, если API её предоставляет.
- Логировать окончательный отказ после исчерпания попыток.

## SQLite

- Различать ожидаемый конфликт данных, временную блокировку и нарушение целостности.
- Делать rollback при ошибке транзакции.
- Не сообщать пользователю SQL, параметры запросов и внутреннюю структуру БД.
- Не скрывать ошибки миграции и целостности; останавливать небезопасное продолжение операции.

## Защита данных

- Не отправлять пользователю или администратору traceback, текст внутреннего исключения, токены, содержимое `.env`, SQL и пути проекта.
- Не записывать секреты и полные пользовательские данные в лог.
- Уведомлять администратора кратко; технические детали сохранять только в локальном логе.
- Не запускать polling для проверки обработчиков без прямой просьбы пользователя.
