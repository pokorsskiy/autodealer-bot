# Рабочие правила Codex для autodealer-bot

## Язык и стиль работы

- Общаться с пользователем на русском, коротко и по делу.
- Перед нетривиальными изменениями сначала показывать план и ждать явного согласования.
- Делать минимальные изменения в рамках поставленной задачи; не рефакторить посторонние части проекта.

## Структура проекта

- `autodealer_bot/` — основной Telegram-бот Dealer Auto. Запуск: `python -m autodealer_bot.autodealer`.
- `showcase_telegram_bot/` — демонстрационный бот, где сценарии работают внутри Telegram.
- `showcase_webapp_bot/` — демонстрационный бот с интерфейсом Telegram Web App.
- `showcase_hybrid_bot/` — комбинированный демонстрационный бот: Telegram + Web App.
- Не смешивать модули основного бота и showcase-ботов между собой.
- `check_project.py` — диагностика основного бота из корня репозитория.
- `.env` и SQLite-файлы — локальные данные; не переносить, не раскрывать и не коммитить.

## Локальный запуск

- Основной бот: `python -m autodealer_bot.autodealer`.
- Telegram showcase: `python showcase_telegram_bot/bot.py`.
- Web App showcase: `python showcase_webapp_bot/bot.py`.
- Hybrid showcase: `python showcase_hybrid_bot/bot.py`.
- Web App-фронтенд находится в `showcase_webapp_bot/web/` и публикуется как статический сайт.

## Разработка Telegram-ботов

- Настройки получать через переменные окружения; новые секреты и токены в код не добавлять.
- Пользовательский текст при `parse_mode='HTML'` экранировать через `html.escape`.
- Клавиатуры хранить в `keyboards.py`, работу с SQLite — в `database.py`, логи — в `logger.py`.
- Для SQLite использовать контекстные менеджеры и не терять данные при миграциях.

## Навыки и расширения

- При изменениях Telegram-ботов использовать `telegram-bot-builder`.
- При изменениях схемы или данных SQLite использовать `db-migrator`.
- Для обработки исключений и уведомлений об ошибках использовать `error-handler`.
- Для текстов, кнопок и меню Telegram использовать `ui-designer`.
- Браузер, документы, таблицы, PDF и генерацию изображений подключать только для задач, где они действительно нужны.

## Проверка

- После изменения Python-кода запускать доступные проверки: синтаксис, целевой диагностический скрипт и/или тесты.
- Перед запуском бота убедиться, что `BOT_TOKEN` и `YOUR_CHAT_ID` заданы в `.env` или окружении.
- После изменения Web App проверять `index.html`, `style.css` и `app.js`; перед публикацией убеждаться, что сайт открывается по HTTPS.

## Git и безопасность

- Перед `git commit` показать `git diff` и запросить отдельное явное разрешение.
- Перед `git push` запросить отдельное явное разрешение.
- В коммит не включать `.env`, `*.db`, токены, ключи, пароли и временные файлы.
- Один логический коммит должен содержать одно изменение.
