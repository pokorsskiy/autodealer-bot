# Рабочие правила Codex для showcase_bot

## Язык и стиль работы

- Общаться с пользователем на русском, коротко и по делу.
- Перед нетривиальными изменениями сначала показывать план и ждать явного согласования.
- Делать минимальные изменения в рамках поставленной задачи; не рефакторить посторонние части проекта.

## Структура проекта

- `showcase_bot/` — основной Telegram-бот. Запуск: `python showcase_bot/bot.py`.
- `showcase_telegram_bot/` — дополнительный демонстрационный бот, где сценарии работают внутри Telegram.
- `showcase_webapp_bot/` — дополнительный демонстрационный бот с интерфейсом Telegram Web App.
- `showcase_hybrid_bot/` — дополнительный комбинированный бот: Telegram + Web App.
- Не смешивать модули `showcase_bot/` и дополнительных showcase-ботов между собой.
- `showcase_bot/check_project.py` — диагностика основного бота.
- `.env` и SQLite-файлы — локальные данные; не переносить, не раскрывать и не коммитить.

## Область изменений

- По умолчанию изменять только `showcase_bot/` и связанные с ним файлы в корне проекта.
- `showcase_telegram_bot/`, `showcase_webapp_bot/` и `showcase_hybrid_bot/` изменять только по прямому запросу пользователя.
- Не переносить код между ботами без отдельного согласования.

## Главные файлы

- `showcase_bot/bot.py` — обработчики Telegram и запуск бота.
- `showcase_bot/config.py` — загрузка настроек из окружения.
- `showcase_bot/database.py` — работа с SQLite.
- `showcase_bot/keyboards.py` — клавиатуры и кнопки.
- `showcase_bot/logger.py` — настройка логирования.
- `showcase_bot/check_project.py` — диагностика структуры и настроек проекта.

## Локальный запуск

- Основной бот: `python showcase_bot/bot.py`.
- Telegram showcase: `python showcase_telegram_bot/bot.py`.
- Web App showcase: `python showcase_webapp_bot/bot.py`.
- Hybrid showcase: `python showcase_hybrid_bot/bot.py`.
- Web App-фронтенд находится в `showcase_webapp_bot/web/` и публикуется как статический сайт.
- Не запускать polling без прямой просьбы пользователя: параллельный экземпляр может конфликтовать с уже работающим ботом.

## Разработка Telegram-ботов

- Настройки получать через переменные окружения; новые секреты и токены в код не добавлять.
- Пользовательский текст при `parse_mode='HTML'` экранировать через `html.escape`.
- Клавиатуры хранить в `keyboards.py`, работу с SQLite — в `database.py`, логи — в `logger.py`.
- Для SQLite использовать контекстные менеджеры и не терять данные при миграциях.
- На callback-запросы отвечать через `answer_callback_query`; учитывать ограничение Telegram на размер callback-данных.
- Не показывать пользователю traceback и внутренние сообщения об ошибках.
- Сетевые операции выполнять с обработкой таймаутов и ожидаемых исключений.

## SQLite и локальные данные

- Не удалять, не очищать и не пересоздавать рабочую базу данных без отдельного разрешения пользователя.
- Перед изменением схемы проверять существующие таблицы и колонки и сохранять обратную совместимость.
- Перед потенциально рискованной миграцией создавать резервную копию базы данных.
- Не использовать рабочую базу для автоматических тестов.

## Зависимости

- Добавлять новые библиотеки только при необходимости.
- При добавлении или обновлении зависимости одновременно обновлять `requirements.txt`.
- Не устанавливать пакеты глобально и не менять окружение без необходимости.

## Навыки и расширения

- При изменениях Telegram-ботов использовать `telegram-bot-builder`.
- При изменениях схемы или данных SQLite использовать `db-migrator`.
- Для обработки исключений и уведомлений об ошибках использовать `error-handler`.
- Для текстов, кнопок и меню Telegram использовать `ui-designer`.
- Браузер, документы, таблицы, PDF и генерацию изображений подключать только для задач, где они действительно нужны.

## Проверка

- После изменения Python-кода запускать `python -m compileall showcase_bot`.
- После изменений основного бота запускать `python showcase_bot/check_project.py`, если для этого не требуются отсутствующие секреты или внешние сервисы.
- Если для изменяемой части есть тесты, запускать соответствующие тесты.
- Перед запуском бота убедиться, что `BOT_TOKEN` и `YOUR_CHAT_ID` заданы в `.env` или окружении.
- После изменения Web App проверять `index.html`, `style.css` и `app.js`; перед публикацией убеждаться, что сайт открывается по HTTPS.

## Критерии готовности

- Изменён только код, относящийся к поставленной задаче.
- Python-код проходит проверку синтаксиса и доступную диагностику.
- Секреты, локальные базы данных и временные файлы не попали в изменения.
- В результате перечислены изменённые файлы и выполненные проверки.
- Известные ограничения или невыполненные проверки явно сообщены пользователю.

## Git и безопасность

- Перед `git commit` показать `git diff` и запросить отдельное явное разрешение.
- Перед `git push` запросить отдельное явное разрешение.
- В коммит не включать `.env`, `*.db`, токены, ключи, пароли и временные файлы.
- Один логический коммит должен содержать одно изменение.
